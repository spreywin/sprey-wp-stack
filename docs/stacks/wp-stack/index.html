STACK · V1.0

Sprey WP Stack

A compact, production-oriented WordPress and WooCommerce deployment for a modest VPS. Caddy is the only public service; WordPress, MariaDB and optional phpMyAdmin remain behind Docker networking.

InstallRepository

ARCHITECTURE

A website stack, not a server control panel.

Internet
80 · 443 · HTTP/3
↓
Caddy
HTTPS · proxy · compression
↓
WordPress + WooCommerce
private Docker network
↓
MariaDB LTS
private Docker network

No CloudPanel, Webmin or Portainer is required. phpMyAdmin is disabled by default and binds only to localhost when its optional profile is started.

QUICK START

Fresh Ubuntu or Debian VPS.

Point DNS to the VPS, clone the repository and run the installer. It installs Docker when required, generates database credentials, configures UFW and starts the stack.

terminal
git clone https://github.com/spreywin/sprey-wp-stack.git
cd sprey-wp-stack
sudo ./install.sh example.com admin@example.com

BTCPAY SERVER

WooCommerce integration.

V1.0 uses the current BTCPay for WooCommerce V2 integration. The BTCPay Server itself is separate infrastructure; this stack hosts the WooCommerce side of the integration. Detailed installation and API-key connection steps will live under the shared Integrations section of Sprey Docs.

CLOUDFLARE · V1.0

Proxy plus outage fallback.

Production uses Full (strict) TLS and avoids caching dynamic WooCommerce routes. The v1 design also includes a static Cloudflare Pages outage origin for periods when the WordPress VPS fails health checks. The fallback is informational only: cart, account and checkout remain unavailable while the application origin is down.

OPERATIONS

Keep production boring.

Status

docker compose ps

Logs

docker compose logs -f caddy

Update

docker compose pull && docker compose up -d

Back up MariaDB and WordPress uploads before upgrades. Never run docker compose down -v on a production deployment.
