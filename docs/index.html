QUICK START

Fresh Ubuntu or Debian VPS.

Point the domain DNS record to the server first. Then clone the project and run the installer as root.

It installs Docker when required, creates a protected .env, configures UFW and starts the containers.

terminal
git clone https://github.com/spreywin/sprey-wp-stack.git
cd sprey-wp-stack
sudo ./install.sh example.com admin@example.com
01

Secure minimum

UFW allows only SSH, HTTP, HTTPS and HTTP/3. The database is never exposed publicly.

02

Current releases

WordPress follows the stable PHP 8.4 image while MariaDB stays on its LTS line.

03

Simple operations

Routine administration uses standard Docker Compose commands over SSH. No Portainer or CloudPanel.

OPERATIONS

The three commands used most often.

Status

docker compose ps

Caddy logs

docker compose logs -f caddy

Update

docker compose pull && docker compose up -d

Back up the database and wp-content/uploads before upgrading WordPress, WooCommerce or MariaDB. Never run docker compose down -v on a production server.

BTCPAY SERVER

WooCommerce payments without custody.

Version 1.0 documents integration with the current BTCPay for WooCommerce V2 plugin. BTCPay Server remains separate payment infrastructure; the WordPress stack only hosts the WooCommerce integration.

CLOUDFLARE — V1.0

CDN in front. Static outage page behind.

Use Cloudflare with Full (strict) TLS and bypass caching for cart, checkout, account and WordPress admin routes. Version 1.0 also includes an outage-page design: Cloudflare Pages may serve a static maintenance page when health checks mark the WordPress origin unavailable. It is an outage fallback, never a live WooCommerce replacement.
